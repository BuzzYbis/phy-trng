## Selection criteria

Candidates are a precisely specified sponge/duplex with explicit ratchet, Hash_DRBG under 90A, and the KS24 ¶994–995 example construction. Prefer evidence clarity, known assumptions and compatible proof scope over superficial code size. A generic XOF API is not a generator construction.

For each candidate answer: irreversible state evolution under full-state compromise; actual request-state schedule and selected secrecy granularity; adversarial additional input; entropy transfer to state and final output; domain separation; reseed freshness; compromise recovery and erasure. Describe the nine-tuple after choosing the construction.

## B-ARG-02 — security properties

Keccak-f is invertible, so the construction must explain what makes the relevant update one-way. Overwrite/truncation/ratcheting require a stated security parameter and argument; merely discarding some bits is not enough. Distinguish primitive correctness, constant-time/leakage properties and construction security.

Analyze state exposure before, between and after output blocks. Choose per-internal-number enhanced backward secrecy or request granularity with conceptual atomicity, and justify both request-state and persistent-state transitions. Domain separation constants and additional-input length/encoding are part of the specification.

## B-ARG-03 — resulting DRG.4 state

Analyze the complete seeding/reseeding mapping from qualified PTG.3 output to effective internal state; account for previous state, personalization and attacker-known input. Show ≥240 bits min-entropy in that state and classify ≥246 effective computational state bits separately. Counting seed bytes or testing subsequent output cannot establish the transfer.

Specify cached seed generation/consumption, maximum age, secrecy boundary, failed-seed erasure and recovery after compromise. A compromised reservoir cannot supply fresh recovery entropy merely because it was generated by a TRNG earlier.

## B-ARG-06 — PTG.3.4

For each intermediate input, define n_int and generated m_ptg, require c_rate≥1 and analyze narrow maps/state widths. Count seed-directed, test-directed and discarded output as generated output. Use minimum guaranteed variable input length, never a sliding average to disguise expansion. This obligation is necessary but distinct from output entropy.

## B-ARG-09 — complete PTG.3.5 output transfer

Select the explicit min-entropy claim, at least 0.98/bit. Analyze the mapping from the latest intermediate block to final PTG.3 output with the old state treated according to KS24 ¶402–403. Decompose reseeding, absorb, internal hashing/bottlenecks, state update and output/truncation. Apply the applicable ¶391–413 analysis and specify undercut probability; where using the AIS random-mapping method, include its 2^-16 criterion and mathematical applicability conditions.

Work through the actual candidate dimensions. n_int=512 at v_m=0.5 and m_ptg=256 is only a proposal. KS24 ¶411(i) shows why a 256-bit state and a 256-bit hash output need not justify 0.98/bit even with ideal state entropy. Add input, change state/path width, truncate output or select another construction as the analysis requires. A successful ≥240-bit state proof does not imply the ≥250.88 bits needed for 256 output bits at 0.98.

Freeze n_int, m_ptg, c_rate, actual bottleneck dimensions, v_out, seed requirements and attainable PTG.3 target **only after** the argument closes. If Stage 1 block dimensions change, rerun/review B-ARG-01 and dependent G2 evidence. The 16 kbit/s aspiration may change by a documented design decision.

## Backend and vectors

Keccak/Formosa profiles require the exact supported artifacts and a genuinely independent oracle. Soft-primary Keccak is valid with its own proof/vector/reference evidence. SHA-256 selection requires SHA-256 code plus FIPS 180-4 and applicable 90A/construction vectors; Formosa Keccak gates become not applicable, not failures or substitute evidence.

Run 10^6 host and 10^4 target differential cases, applicable official vectors and adversarial boundary cases. Confirm three relevant corrupted variants fail self-test. Record exact KAT provenance; do not require every Keccak-derived function if not used.
